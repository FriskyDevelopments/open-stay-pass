# Open Stay Pass: Open-Source Monetization Architecture

## Principle

Open Stay Pass is valuable before purchase. The free MIT core must always support a signed QR arrival or handoff link, Spanish-first guest continuity, Folios proof handoff, expiry, and revocation. Revenue begins only when an operator asks the team to run, integrate, brand, or support the system beyond that self-hostable core.

## Value ladder

| Offer | Buyer outcome | Why it remains optional | Delivery boundary |
|---|---|---|---|
| Open-source core | Start with QR and a secure mobile credential | The default public path | MIT code, self-hosted setup, documented adapter contracts |
| Implementation sprint | Launch a first property or evidence workflow | Operators can still self-implement | Fixed-scope setup, bilingual configuration, staff handover |
| Managed operator workspace | Avoid operating credentials, updates, and monitoring alone | QR-first core keeps working without it | Managed hosting, backups, observability, operator support |
| Wallet operations | Issue and maintain Apple/Google Wallet passes | Requires platform credentials and ongoing certificate/key operations | Certificate/issuer setup, update service, lifecycle monitoring |
| Verified connector pack | Connect a specific PMS, channel manager, or lock provider | No connector is required for the core | Provider-specific adapter, permission review, lifecycle test suite |
| AI continuity | Scale grounded guest answers from approved property content | Local fallback stays available | Usage-metered model access, retrieval controls, evaluation and support |
| Smart-lock design service | Connect an audited access provider safely | Locks must never be coupled to QR/NFC/Wallet payloads | Provider evaluation, access-window design, webhook/audit integration |

## Packaging sequence

The first commercial offer should be an implementation sprint because it converts a clear operational outcome into a bounded engagement. Managed hosting follows when operators ask for reliability and team access. Wallet operations and verified connectors become add-ons only after a concrete provider and operator use case are confirmed. AI usage is sold as a transparent operating cost and support layer, not as an authorization engine.

## Community support

Ko-fi, NOWPayments, and Wise Business are voluntary support links. They do not unlock access, change trust level, grant credential privileges, or receive guest data. They are a participation path for users who value the open core, not a substitute for a commercial support agreement.

## Anti-patterns

Do not paywall revocation, hide security fixes, publish lock credentials in a client payload, create artificial feature scarcity, fabricate traction, or promise that a wallet, NFC, or physical-access integration is active before official credentialing and end-to-end validation.

## First measurements

Track only decisions that improve the product: successful demo credential creation, second-device QR resolution, NDEF URL copy, issued-CFDI Wallet eligibility, README-to-demo visits, GitHub stars after a successful setup, and qualified implementation inquiries. Do not collect guest content or use external support links as a behavioral gate.
