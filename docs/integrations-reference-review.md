# Integrations Reference Review

The supplied bundled `index.html` is a Folios-oriented interactive reference rather than an executable dependency. Its visible copy emphasizes a **sovereign operations layer**, a **Folios terminal**, concise status records, and an evidence-first operational tone. Its large embedded runtime was not executed.

## Compatible patterns adopted

| Reference pattern | Open Stay Pass adaptation | Security boundary |
|---|---|---|
| Terminal language and command receipt | Credential copy produces a short terminal-style confirmation | Only a truncated URL fingerprint and public lifecycle status are shown; never the token |
| Dense record rows | Integrations keep explicit capability, state, and owner boundaries | A UI status is not authorization and does not trigger a provider request |
| Folios Ink/Paper/Cyan/Signal palette | The integrations surface uses the existing Brandbook v2 semantic tokens | Signal stays reserved for verified decisions rather than generic decoration |
| “For machines” operational clarity | NFC and lock adapter docs distinguish carriers from provider-owned provisioning | No lock credential, PIN, or unlock action is placed in QR, NFC, Wallet, or browser state |

## Patterns intentionally not copied

The reference’s broad desktop-operation concept and any product-specific desktop/CLI claims are not copied into the guest-arrival flow. Open Stay Pass remains Spanish-first, mobile-first, and QR-first. The terminal effect is an optional feedback affordance, not a command surface and not a new authentication mechanism.
